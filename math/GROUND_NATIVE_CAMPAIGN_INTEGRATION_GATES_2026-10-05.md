# Native campaign verification and integration gates

The goal remains restoration of the original mathematical claims where they are
true and feasible. The finite native-source campaign is one part of that goal.
Its completion does not repair previously identified false or project-sized
physical, universal or continuum claims. The paper and original runtime are not
to be edited in this campaign.

## Source and proof coverage

`scripts/de_native_campaign_verify.py` has two explicit stages. The `source`
stage checks 1734 main and four supplemental modules against their private and
qualified source hashes, reproduces the import-only source translation, derives
each theorem's namespace/name directly from its source, checks the import DAG
and all 23 external source imports, and compares both fresh manifests to the
derived declaration lists. It preserves the explicit entry premises in the four
conditional real-cycle bridges and checks that the two generated unconditional
wrappers have no exported entry premise.

The aggregate coverage check preserves the original twelve stored binary
couplings and exact original-seed native map. Sixty-update diagnostics and
successful prefixes among updates 1–60 have the sample-index cutoff `< 9`;
state limits and eventual diagnostic success have cutoff `< 10`. Thus the
coupling labelled 15 fails the sixty-update diagnostics but converges and
eventually passes. The actual phase convention and both mathematical initial
normalizations remain in the imported source. Source enumeration is not kernel
proof completion.

The source stage also revalidates all 1831 inputs of the completed exact replay,
the 1070 leaf hashes, all ten payload hashes, the exact stored couplings, the
1070/535 step/pair coverage and the completed replay log. It consumes the prior
full arithmetic run without calling a numerical solver or rerunning an unchanged
1070-step certificate calculation. No IEEE trace follows from this check.

The `qualified` stage additionally requires both completed qualified summaries,
the exact driver completion markers, all source freezes, all 1738 fresh module
terminal records, source/object/log hashes, all 20634 printed statements and
all 20634 transitive axiom closures. Only `propext`, `Classical.choice` and
`Quot.sound` may occur. The actual printed aggregate statements must retain the
finite/eventual cutoffs. Missing qualified receipts cause rejection. Neither
stage infers repository integration or complete original-paper restoration.

Coverage controls reject missing or duplicated axiom closures, an additional
local axiom in a transitive closure, missing or reordered printed statements,
an invalid namespace ending and an unterminated block comment. Valid nested
comments, namespace declarations, statements and axiom-free/standard-only audit
entries pass. These are verifier controls, not new mathematical theorems.

1. Finish the whole-background-box driver and its 6909 fresh statement/axiom
   checks. Run its exact replay/semantic verifier and preserve its existing
   raw-prefix audit before appending the native campaign to the default
   registration. Its verifier expects the current main-only registration.
2. Finish both the 1734-module qualified campaign and the separate four-module
   seed-real supplement. Their source freezes remain mandatory until terminal;
   do not change registered Lean sources, `lakefile.lean`, or protected plans
   while either is running.
3. Run `de_native_campaign_verify.py --stage qualified` and preserve its terminal
   result and exact proof receipts. Archive all fresh module/audit records with
   the exact source, plans, replay and toolchain identities.
4. Install each qualified `.lean` file at its planned repository module path,
   with byte equality against the freshly checked source. Append all 1738 roots
   and 20634 declarations to the default registration/audit manifest while
   preserving the earlier manifest byte prefix. Preserve both supplemental
   fresh manifests and the main fresh manifests. Fresh qualified objects may
   be reused only at their matching qualified paths and source hashes.
5. Build the registered repository and verify source installation, registration,
   complete theorem coverage, current exported statement shapes and audit
   provenance. Preserve the historical raw audits, rather than representing a
   concatenated receipt as a fresh rerun of all cumulative declarations.
6. Update the mathematical coverage records and READMEs to the scope actually
   checked, run the applicable final semantic verifiers, commit the completed
   packet(s), and check the resulting worktree. Leave the paper unchanged.
